# RV32M Radix-2 恢复式除法器功能指导性 SPEC

- 文档版本：v0.1
- 目标架构：RV32
- ISA范围：RISC-V `M`扩展中的 `DIV`、`DIVU`、`REM`、`REMU`
- 推荐微架构：Radix-2 恢复式、每周期生成1位商、32次迭代
- 目标工艺与频率：55 nm、SS综合库、75 MHz
- 文档性质：功能与合规性指导规范，不定义具体RTL端口、流水级连接、模块层次或信号命名

---

## 1. 文档约定

本文使用以下关键词：

- **必须（MUST）**：为满足RISC-V架构语义或本项目V1功能目标必须实现。
- **不得（MUST NOT）**：违反后将造成架构不合规或明确的功能错误。
- **建议（SHOULD）**：推荐的V1实现方式；可根据现有处理器结构调整，但调整后仍必须满足全部架构要求。
- **可选（MAY）**：不影响基础功能合规性的优化。

本文将要求分为两类：

1. **ISA要求**：软件可见，必须严格遵守。
2. **微架构指导**：软件不可见，用于指导V1实现，可由agent结合现有核设计细化。

## 3. 标准依据与扩展声明

### 3.1 标准版本

本设计以RISC-V Unprivileged ISA中：

- **“M” Extension for Integer Multiplication and Division, Version 2.0**

为架构语义依据。

### 3.2 `M`扩展声明要求

**ISA-COMP-001（MUST）**  
只有当处理器实现了RV32 `M`扩展规定的全部乘法和除法指令时，才能将处理器声明为`RV32IM`或在实现了`misa` CSR时置位`misa.M`。

**ISA-COMP-002（MUST）**  
本SPEC只覆盖`M`扩展中的除法子集，不能单独作为完整`M`扩展合规依据。

**ISA-COMP-003（MUST）**  
RISC-V定义了仅包含乘法的`Zmmul`扩展，但没有与之对应的标准“仅除法”子扩展。因此，在完整乘法部分完成前，不得仅凭本除法器宣称支持`M`扩展。

## 4. 指令定义与译码

四条指令均采用R-type格式：

```text
31          25 24      20 19      15 14  12 11       7 6        0
+-------------+----------+----------+------+-----------+----------+
|   funct7    |   rs2    |   rs1    |funct3|    rd     |  opcode  |
+-------------+----------+----------+------+-----------+----------+
```

统一字段：

```text
opcode = 7'b0110011
funct7 = 7'b0000001
```

| 指令 | funct3 | `rs1`含义 | `rs2`含义 | `rd`结果 |
|---|---:|---|---|---|
| `DIV`  | `3'b100` | 有符号被除数 | 有符号除数 | 有符号商 |
| `DIVU` | `3'b101` | 无符号被除数 | 无符号除数 | 无符号商 |
| `REM`  | `3'b110` | 有符号被除数 | 有符号除数 | 有符号余数 |
| `REMU` | `3'b111` | 无符号被除数 | 无符号除数 | 无符号余数 |

**ISA-DEC-001（MUST）**  
操作数顺序必须为：

```text
rs1 / rs2
```

不得交换被除数和除数。

**ISA-DEC-002（MUST）**  
当实现声明支持`M`扩展时，上述四种合法编码不得被报告为非法指令。

**ISA-DEC-003（MUST）**  
若实现通过配置关闭`M`扩展，则这些编码应由处理器统一的非法指令机制处理，而不是由除法器自行产生算术异常。

**ISA-DEC-004（MUST）**  
`rd=x0`时仍应保持标准RISC-V语义：计算结果不得改变架构状态。是否跳过实际迭代属于微架构优化，不由本SPEC规定。

## 5. 架构语义

设：

```text
A = rs1中的32位原始值
B = rs2中的32位原始值
Q = 商
R = 余数
```

### 5.1 `DIV`

**ISA-FUNC-001（MUST）**

- 将`A`和`B`解释为32位二进制补码有符号整数；
- 计算`A / B`；
- 商必须向零取整；
- 将32位二进制补码结果写入`rd`。

正常非特殊情况下：

```text
Q = trunc_toward_zero(A / B)
```

### 5.2 `DIVU`

**ISA-FUNC-002（MUST）**

- 将`A`和`B`解释为32位无符号整数；
- 计算无符号商；
- 将商写入`rd`。

正常非特殊情况下：

```text
Q = floor(A / B)
```

### 5.3 `REM`

**ISA-FUNC-003（MUST）**

- 将`A`和`B`解释为32位二进制补码有符号整数；
- 返回与`DIV`对应的余数；
- 非零余数的符号必须与被除数`A`相同。

正常非特殊情况下：

```text
R = A - B × trunc_toward_zero(A / B)
```

### 5.4 `REMU`

**ISA-FUNC-004（MUST）**

- 将`A`和`B`解释为32位无符号整数；
- 返回与`DIVU`对应的无符号余数。

正常非特殊情况下：

```text
R = A mod B
```

### 5.5 商余关系

**ISA-FUNC-005（MUST）**  
除有符号溢出情况外，有符号和无符号除法均必须满足：

```text
被除数 = 除数 × 商 + 余数
```

**ISA-FUNC-006（MUST）**  
当除数非零时，正常运算结果必须满足：

```text
|余数| < |除数|      // 有符号运算
余数  < 除数        // 无符号运算
```

**ISA-FUNC-007（MUST）**  
`REM`的结果为零时不存在正负零区别，结果必须为`32'h0000_0000`。

## 6. 特殊情况

### 6.1 除数为零

RISC-V整数除法的除零行为不产生算术异常或陷阱，而是返回标准规定的结果。

| 指令 | 条件 | 结果 |
|---|---|---|
| `DIV`  | `B == 0` | `32'hFFFF_FFFF` |
| `DIVU` | `B == 0` | `32'hFFFF_FFFF` |
| `REM`  | `B == 0` | 原始被除数`A` |
| `REMU` | `B == 0` | 原始被除数`A` |

**ISA-SPEC-001（MUST）**  
除数为零不得由除法器请求除零异常、算术异常或同步陷阱。

**ISA-SPEC-002（MUST）**  
除零时，`REM`和`REMU`必须返回未经绝对值转换、符号转换或其他修改的原始`rs1`位模式。

### 6.2 有符号除法溢出

RV32有符号除法只有一种溢出情况：

```text
A = 32'h8000_0000    // -2^31
B = 32'hFFFF_FFFF    // -1
```

标准结果：

| 指令 | 结果 |
|---|---|
| `DIV` | `32'h8000_0000` |
| `REM` | `32'h0000_0000` |

**ISA-SPEC-003（MUST）**  
有符号溢出不得产生异常或陷阱。

**ISA-SPEC-004（MUST）**  
`DIVU`和`REMU`不存在对应的无符号溢出特殊情况。

### 6.3 特殊情况优先级

推荐判定顺序：

```text
1. B == 0
2. signed_op && A == 32'h8000_0000 && B == 32'hFFFF_FFFF
3. 正常除法流程
```

除零和有符号溢出的条件互斥，因此只要最终结果正确，具体优先级不构成架构可见差异。

特殊情况是否旁路迭代、是否保持与普通除法相同延迟，不由RISC-V ISA规定。

## 7. V1推荐微架构

### 7.1 总体方案

V1建议采用：

```text
Radix-2恢复式除法
每次迭代生成1位商
正常运算执行32次迭代
有符号运算转换为幅值无符号除法
迭代结束后进行符号恢复
同一次除法同时得到商和余数
```

**uARCH-001（SHOULD）**  
使用一个统一的无符号除法核心支持全部四条指令。

**uARCH-002（SHOULD）**  
符号处理应位于无符号迭代核心的输入和输出边界，避免在每轮迭代中执行有符号运算。

**uARCH-003（SHOULD）**  
V1可只支持一个在途除法操作。在当前操作结束、取消或结果被接收前，不接收下一项除法操作。

**uARCH-004（SHOULD）**  
V1不要求流水化，不要求每周期接收一条除法指令。

### 7.2 推荐数据宽度

建议至少包含等价于以下信息的状态：

| 状态 | 推荐宽度 | 用途 |
|---|---:|---|
| 被除数幅值/移位状态 | 32 bit | 提供每轮下移的被除数位 |
| 除数幅值 | 32 bit | 无符号除数 |
| 部分余数 | 33 bit | 保存左移后可能达到33位的试探余数 |
| 商 | 32 bit | 保存逐位产生的商 |
| 迭代计数 | 至少6 bit | 表示0～32轮 |
| 操作类型 | 实现自定 | 区分商/余数和有符号/无符号 |
| 商符号信息 | 1 bit | 有符号商结果修正 |
| 余数符号信息 | 1 bit | 有符号余数结果修正 |

**uARCH-005（MUST）**  
部分余数相关运算必须提供足够的扩展位，避免32位左移或减法产生的进位/借位被错误截断。推荐使用33位部分余数和33位零扩展除数。

## 8. 有符号操作数预处理

仅`DIV`和`REM`执行有符号预处理。

定义：

```text
a_neg = A[31]
b_neg = B[31]

a_mag = a_neg ? ((~A + 1) mod 2^32) : A
b_mag = b_neg ? ((~B + 1) mod 2^32) : B

q_neg = a_neg XOR b_neg
r_neg = a_neg
```

对`DIVU`和`REMU`：

```text
a_mag = A
b_mag = B
q_neg = 0
r_neg = 0
```

**uARCH-SIGN-001（MUST）**  
`DIV`的商符号由被除数和除数符号异或决定。

**uARCH-SIGN-002（MUST）**  
`REM`的非零余数符号只由被除数符号决定，与除数符号无关。

**uARCH-SIGN-003（MUST）**  
绝对值计算必须采用32位模`2^32`补码运算。因此：

```text
abs(32'h8000_0000)的位模式仍为32'h8000_0000
```

该位模式在无符号核心中代表幅值`2^31`，属于合法输入。

**uARCH-SIGN-004（SHOULD）**  
除零和有符号溢出建议在进入正常幅值迭代前识别，以避免特殊结果被后续符号修正破坏。

## 9. Radix-2恢复式迭代定义

### 9.1 初始化

对于非特殊情况：

```text
partial_rem = 0
quotient    = 0
dividend    = a_mag
divisor     = b_mag
```

### 9.2 数学等价迭代

以下伪代码定义V1推荐算法的功能等价行为。寄存器布局和移位方向可调整，但最终行为必须等价。

```text
partial_rem = 0
quotient    = 0

for i = 31 downto 0:
    trial_rem = (partial_rem << 1) | dividend[i]

    if trial_rem >= divisor:
        partial_rem = trial_rem - divisor
        quotient[i] = 1
    else:
        partial_rem = trial_rem
        quotient[i] = 0
```

其中：

- `trial_rem`和`partial_rem`按无符号数处理；
- 比较必须为无符号比较；
- `divisor`在正常迭代期间必须非零；
- 每次迭代产生一位商；
- 共执行32次迭代。

该算法称为恢复式，是因为试减不成立时保留减法前的`trial_rem`，等价于恢复部分余数。

### 9.3 每轮不变量

**uARCH-ITER-001（MUST）**  
在每轮完成后应满足：

```text
0 <= partial_rem < divisor
```

**uARCH-ITER-002（MUST）**  
正常路径必须处理全部32个被除数位，不得少迭代或多迭代。

**uARCH-ITER-003（MUST）**  
迭代比较必须使用无符号语义。不得因SystemVerilog的隐式signed类型传播而将最高位为1的幅值误判为负数。

**uARCH-ITER-004（SHOULD）**  
可以使用减法器的借位/进位信息完成`trial_rem >= divisor`判断，但实现必须对所有33位输入保持无符号等价性，不得简单依赖未经证明的有符号符号位判断。

### 9.4 迭代结果

32轮结束后：

```text
q_mag = quotient
r_mag = partial_rem[31:0]
```

此时：

```text
a_mag = b_mag × q_mag + r_mag
0 <= r_mag < b_mag
```

## 10. 结果符号恢复

### 10.1 商

对于`DIV`：

```text
Q = q_neg ? ((~q_mag + 1) mod 2^32) : q_mag
```

对于`DIVU`：

```text
Q = q_mag
```

### 10.2 余数

对于`REM`：

```text
R = r_neg ? ((~r_mag + 1) mod 2^32) : r_mag
```

对于`REMU`：

```text
R = r_mag
```

**uARCH-POST-001（MUST）**  
结果选择必须由原始指令类型决定：

```text
DIV/DIVU -> 返回Q
REM/REMU -> 返回R
```

**uARCH-POST-002（MUST）**  
商和余数的符号修正规则不得互换。

**uARCH-POST-003（MUST）**  
输出符号修正不得应用于除零标准结果和有符号溢出标准结果，除非实现能够证明修正后仍严格得到规定值。

## 11. 延迟与执行行为

### 11.1 ISA可见要求

**EXEC-001（MUST）**  
除法指令的精确延迟不属于RISC-V架构语义。不同操作数、不同指令或特殊情况可以具有不同延迟。

**EXEC-002（MUST）**  
一条未被取消的合法除法指令最终只能产生一次架构结果，不得重复写回。

**EXEC-003（MUST）**  
除法执行期间不得暴露或提交中间商、部分余数或未修正符号的结果。

**EXEC-004（MUST）**  
若指令因更老的异常、分支重定向、flush或其他处理器既有取消机制而被取消，则该指令不得写回架构寄存器。

**EXEC-005（MUST）**  
结果因下游阻塞而暂时不能提交时，必须保持结果和对应指令身份稳定，直到被接收或取消。具体握手机制由集成设计确定。

### 11.2 V1推荐延迟组织

V1可采用以下逻辑阶段：

```text
接收/锁存
特殊情况检测与幅值准备
32轮迭代
结果符号恢复
结果提交
```

可将相邻步骤合并，以减少周期。建议正常操作的核心迭代固定为32周期，但本SPEC不强制总延迟为某个精确数值。

特殊情况可提前完成，也可保持固定延迟。

## 12. 复位、取消与异常边界

**CTRL-001（MUST）**  
复位后除法器不得凭空产生有效结果。

**CTRL-002（MUST）**  
被取消操作的内部状态不得在之后产生迟到写回。

**CTRL-003（MUST）**  
除零不是异常；不得将处理器的通用flush/kill机制误用于“处理”除零。

**CTRL-004（MUST）**  
除法器内部故障之外，四条标准除法指令不应自行生成算术异常。

**CTRL-005（SHOULD）**  
取消后可立即返回空闲，也可先清理内部状态；但取消操作不得阻塞到旧结果被提交。

## 13. 55 nm SS、75 MHz实现指导

75 MHz对应时钟周期约：

```text
Tclk = 13.333 ns
```

V1推荐将单轮关键路径限制为：

```text
部分余数寄存器
 -> 左移并拼接下一位被除数
 -> 33位无符号比较/减法
 -> 余数与商位选择
 -> 部分余数/商寄存器
```

**PPA-001（SHOULD）**  
每周期只展开一次Radix-2迭代，不在V1中串联两级或更多级减法。

**PPA-002（SHOULD）**  
优先使用独立33位减法数据通路，以减少除法控制对普通ALU关键路径的影响。是否复用ALU由完整核综合结果决定。

**PPA-003（MUST）**  
迭代寄存器之间的路径是逐周期真实路径，必须满足单周期时序。不得因一条除法指令总共执行32轮，就将单轮反馈路径错误设置为32周期multicycle path。

**PPA-004（SHOULD）**  
综合时至少单独检查：

```text
部分余数寄存器 -> 部分余数寄存器
商寄存器       -> 商寄存器
输入锁存       -> 预处理状态
结果修正       -> 结果寄存器
取消/flush     -> 状态控制
```

**PPA-005（SHOULD）**  
可综合RTL中不建议直接使用`/`和`%`实现除法器，以免综合出不可控的组合除法网络。`/`和`%`可用于testbench或参考模型。

**PPA-006（MUST）**  
最终是否满足75 MHz，必须以目标55 nm SS库下完整处理器综合及后续实现报告为准，不能仅根据算法结构推断。

## 14. RTL实现常见错误约束

**RTL-001（MUST NOT）**  
不得将`DIV`实现为向负无穷取整。RISC-V要求向零取整。

示例：

```text
-7 / 3  = -2
-7 % 3  = -1
```

而不是：

```text
-7 / 3  = -3
-7 % 3  =  2
```

**RTL-002（MUST NOT）**  
不得令`REM`的余数符号跟随除数。

**RTL-003（MUST NOT）**  
不得对除零产生异常。

**RTL-004（MUST NOT）**  
不得将有符号溢出饱和为`32'h7FFF_FFFF`。

**RTL-005（MUST NOT）**  
不得在部分余数比较中混用隐式signed和unsigned表达式。

**RTL-006（MUST NOT）**  
不得在操作被取消后继续提交旧结果。

**RTL-007（MUST NOT）**  
不得把`rs1`和`rs2`的被除数/除数角色交换。

**RTL-008（MUST NOT）**  
不得只实现`DIV`/`DIVU`而让`REM`/`REMU`通过再次运行一个不一致的算法得到不同配对结果。四条指令应共享同一组架构语义和边界处理。

## 15. 验证要求

### 15.1 参考模型

参考模型必须显式处理：

```text
1. 除数为零
2. 32'h8000_0000 / 32'hFFFF_FFFF有符号溢出
3. 有符号向零取整
4. 32位补码结果截取
```

不应直接依赖宿主语言对以下表达式的默认行为：

```text
INT32_MIN / -1
除数为0
负数取模
```

因为不同语言可能产生异常、未定义行为或采用不同取整规则。

### 15.2 定向测试

至少覆盖以下类别：

#### A. 零值

```text
0 / 0
0 / 1
0 / -1
1 / 0
-1 / 0
```

四条指令均需覆盖。

#### B. 有符号溢出

```text
32'h8000_0000 / 32'hFFFF_FFFF
```

检查：

```text
DIV = 32'h8000_0000
REM = 32'h0000_0000
```

#### C. 符号组合

```text
 7 /  3 -> Q= 2, R= 1
-7 /  3 -> Q=-2, R=-1
 7 / -3 -> Q=-2, R= 1
-7 / -3 -> Q= 2, R=-1
```

对应32位结果：

| A | B | `DIV` | `REM` |
|---|---|---|---|
| `7` | `3` | `32'h0000_0002` | `32'h0000_0001` |
| `-7` | `3` | `32'hFFFF_FFFE` | `32'hFFFF_FFFF` |
| `7` | `-3` | `32'hFFFF_FFFE` | `32'h0000_0001` |
| `-7` | `-3` | `32'h0000_0002` | `32'hFFFF_FFFF` |

#### D. 边界值

```text
32'h8000_0000 / 1
32'h8000_0000 / 32'h8000_0000
32'h7FFF_FFFF / 32'hFFFF_FFFF
32'hFFFF_FFFF DIVU 2
32'hFFFF_FFFF REMU 2
32'hFFFF_FFFF DIVU 32'hFFFF_FFFF
```

#### E. 商为零、余数为被除数

```text
|A| < |B|
A = 1, B = 2
A = -1, B = 2
A = 32'h7FFF_FFFF, B = 32'h8000_0000（无符号）
```

#### F. 整除与非整除

```text
A == B
A为B的整数倍
A比B大1
2的幂除数
最大无符号数
最大正有符号数
最小负有符号数
```

### 15.3 随机差分测试

**VERIF-001（MUST）**  
对四条指令执行大规模随机差分测试。

每个非特殊样本至少检查：

```text
A == B × Q + R
```

对于有符号运算还需检查：

```text
R == 0 或 sign(R) == sign(A)
|R| < |B|
Q向零取整
```

对于无符号运算检查：

```text
R < B
```

### 15.4 时序与控制场景

集成后至少验证：

- 操作开始后上游持续保持相同请求时，不得重复接收；
- 结果完成时下游阻塞，结果保持稳定；
- 迭代首轮、中间轮、末轮分别发生flush；
- 完成与flush相邻或同周期时，遵守处理器既有优先级；
- 复位发生在空闲、迭代和结果等待状态；
- 连续执行不同类型的除法指令；
- 除法前后的普通指令写回不被重复或丢失；
- `rd=x0`不改变寄存器状态；
- `rs1==rd`、`rs2==rd`、`rs1==rs2`等合法寄存器组合。

### 15.5 推荐断言

可根据最终接口转换为SVA：

```text
A. 每个被接收且未取消的请求最终对应且只对应一个结果；
B. 未被接收或取消前，已完成结果保持稳定；
C. 被取消请求之后不得产生提交；
D. 正常迭代期间除数幅值非零；
E. 每轮结束后partial_rem < divisor；
F. 正常操作恰好处理32位被除数；
G. 空闲状态不得产生无来源的结果；
H. 复位后不得保留复位前的有效结果。
```

## 16. 验收标准

V1除法器满足以下条件时，可认为达到本SPEC功能目标：

1. 正确识别并执行`DIV`、`DIVU`、`REM`、`REMU`；
2. `rs1`始终作为被除数，`rs2`始终作为除数；
3. 有符号商严格向零取整；
4. `REM`非零余数符号与被除数一致；
5. 除零结果与RISC-V标准一致，且不产生异常；
6. `INT32_MIN / -1`结果与RISC-V标准一致，且不产生异常；
7. 正常结果满足商余恒等式和余数范围约束；
8. 使用功能等价的32轮Radix-2恢复式无符号迭代核心；
9. flush、取消、复位和结果阻塞场景不产生重复、迟到或错误写回；
10. 定向测试和随机差分测试全部通过；
11. 目标55 nm SS综合库下，单轮反馈路径按普通单周期路径约束并满足75 MHz；
12. 在完整`M`扩展全部完成前，不错误宣称处理器已经完整支持`RV32IM`或置位`misa.M`。

## 17. 后续agent需要结合核设计补全的内容

后续详细SPEC或RTL任务应补充：

1. 除法器所在流水级及与EX级的关系；
2. 请求和响应的具体`vld/rdy`边界；
3. 操作接收、busy、完成和结果保持规则；
4. flush/kill的来源、优先级和生效周期；
5. 除法完成后进入EX/MEM还是直接进入统一写回路径；
6. 普通ALU与除法器是否共享加减法资源；
7. 特殊情况是提前返回还是保持固定延迟；
8. 状态机划分和每个状态的寄存器更新；
9. 结果阻塞时哪些内部状态需要保持；
10. 综合约束、模块级时序报告和完整核时序报告；
11. 与乘法器共同组成MDU后的仲裁方式；
12. 与hazard、forwarding、异常和分支flush控制的具体连接。

这些细节可以调整，但不得改变第3～6章规定的软件可见语义。
