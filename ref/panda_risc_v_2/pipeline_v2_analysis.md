# Panda RISC-V 2.0 (迭代版) 流水线与其控制机制分析报告

本文档对 `panda_risc_v_2` 处理器的流水线架构进行了深入分析。该版本引入了乱序执行 (Out-of-Order Execution) 机制，相比第一版在数据冒险处理、前递逻辑、停顿控制和冲刷管理上均有质的飞跃。

---

## 1. 数据冒险检测 (Data Hazard Detection)

`panda_risc_v_2` 放弃了前代的中心化简单监控表，转而采用了 **基于 ROB (Re-Order Buffer) 和发射队列 (Issue Queue) 的依赖性跟踪机制**。

### 实现细节：
- **操作数预取逻辑：** 实现在 `panda_risc_v_regs_rd_out_of_order.v` 模块。指令在分发阶段会同时扫描三个数据源：
    - **ARF (体系结构寄存器堆)：** 获取已退休指令的结果。
    - **ROB (重排序缓存)：** 检查操作数是否由在途指令生成及其是否已就绪。
    - **FU 结果总线：** 检查操作数是否正由某个执行单元完成计算。
- **监听机制 (Listening)：** 如果操作数尚未就绪，指令会携带产生该数据的 **FU ID** 和 **指令序列号 (Tid)** 进入发射队列。
- **WAW/WAR 消除：** 通过 ROB 顺序提交机制，所有寄存器状态的更新仅在指令成为 ROB 头部且确认无误时发生，从而在逻辑层消除了 WAW 和 WAR 冒险。

---

## 2. 数据前递 (Data Forwarding / Bypass)

该版本实现了高度动态的 **多端口前递网络**。

### 实现细节：
- **执行单元广播：** 系统内的 6 个执行单元（ALU, CSR, LSU, Mul, Div, BRU）各自拥有独立的结果总线。
- **IQ 内部前递：** 被阻塞在发射队列中的指令会持续对比 FU 总线上的 `fu_res_tid`。一旦发现所需数据产生，立即在发射队列内捕获数据 (`op1/2_pre_fetched`) 并标记操作数就绪。
- **即时捕获 (Instant Capture)：** 在指令从译码器进入发射队列的瞬间，逻辑也能感知到执行单元当前周期输出的结果并直接装载。

---

## 3. 流水线停顿 (Pipeline Stall)

在乱序架构下，指令间的数据依赖通常由 IQ 吸收，不再导致流水线前端停顿。此时的“停顿”主要源于 **结构性资源耗尽**。

### 实现细节：
- **前端停顿触发点：**
    - **ROB 满 (`rob_full_n`)：** 当重排序缓存无空项时，前端停止取指与分发。
    - **IQ 满 (`m_wr_iq0/1_ready`)：** 当发射队列条目分配失败时，流水线前级反压。
- **控制依赖停顿：** 如 `CSR` 指令为了保证原子性，通常需要等待流水线清空到一定状态才允许发射。
- **访存停顿：** LSU 内部维护 Load/Store 缓冲区，在地址未决或缓冲区溢出时触发停顿。

---

## 4. 流水线冲刷 (Pipeline Flush)

引入了独立的硬件模块 `panda_risc_v_flush_ctrl.v` 对各种冲刷请求进行统一调度。

### 实现细节：
- **优先级仲裁：** 按照 **交付单元 (Commit) > 分支单元 (BRU) > 取指单元 (IFU)** 的优先级对冲刷请求进行仲裁。
- **预测失败处理：** 当 BRU 确认分支预测错误时，不仅会发出 `global_flush_req` 清空所有 IQ 和执行中指令，还会触发 `glb_brc_prdt_rstr_speculative_ghr` 信号，立即恢复推测性的分支历史寄存器 (GHR) 状态。
- **镇压保护 (Suppressing)：** 在总线 ICB 事务进行期间，冲刷请求会被暂时挂起 (`global_flush_pending`)，直到总线进入安全状态后再执行清理，避免协议崩溃。

---

## 5. 版本架构差异对比

| 特性 | Panda RISC-V 1.0 | Panda RISC-V 2.0 (迭代版) |
| :--- | :--- | :--- |
| **基础流水线** | 顺序五级流水线 | **乱序发射 / 顺序退休** |
| **依赖处理** | Centralized Monitor (顺序) | **ROB + Issue Queue (乱序)** |
| **数据前递** | 常规单路径旁路 | **动态总线监听 + IQ 内部数据捕获** |
| **停顿性质** | 数据依赖引发的同步停顿 | **资源满引发的结构停顿** |
| **分支预测** | 基础预测 | **BTB+PHT+RAS 深度预测，支持 GHR 恢复** |

---

## 总结

`panda_risc_v_2` 通过引入乱序执行和复杂的动态调度逻辑，极大地提高了指令级的并行度 (ILP)。其设计难点在于多执行单元环境下的数据总线一致性维护，以及在 speculation (投机执行) 失败后的状态回滚机制。该架构能更有效地隐藏 Load 指令和多周期运算（如除法）带来的延迟。
