# RISC-V LSU 存储指令精细化写入与非对齐访问处理技术报告

## 1. 概述
本报告总结了在 RISC-V 处理器访存单元（LSU）设计中，针对存储指令（SB, SH, SW）的精细化写入需求、主流硬件实现方案，以及非对齐访问（Misaligned Access）的处理策略。

## 2. 存储指令的精细化写入机制

### 2.1 问题描述
RISC-V 指令集支持字节（Byte, 8-bit）、半字（Halfword, 16-bit）和字（Word, 32-bit）级别的存储操作。在 32 位总线架构中，物理内存通常以 32 位为最小寻址字长。当执行 `SB` 或 `SH` 指令时，LSU 必须仅修改目标字中的特定字节，而保持相邻字节内容不变。

直接将窄位宽数据补零扩展为 32 位并执行全字写入会导致覆盖错误，破坏内存中原有的无关数据。

### 2.2 硬件实现方案对比

在硬件层面，解决精细化写入主要有两种技术路径：

| 方案名称 | 实现原理 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- |
| **读-改-写 (Read-Modify-Write)** | 先读出目标 32 位字，在 EX 阶段根据偏移量替换特定字节，再写回 32 位全字。 | 对存储器接口要求低，仅需标准读写信号。 | 存在结构冒险；单口 RAM 需两拍完成；逻辑路径较长。 |
| **字节掩码 (Byte-Strobe / Write Mask)** | 在总线上并行发送 32 位数据和 4 位写掩码（Write Enable Mask），掩码每一位对应一个字节。 | 性能高，一拍完成；接口清晰，符合 AXI/AHB 标准。 | 要求存储器硬件（如 BRAM）必须支持字节级写使能。 |

### 2.3 参考项目分析
*   **TinyRISCV**: 采用了 **读-改-写** 方案。在 `ex.v` 中通过组合逻辑根据内存读回数据拼凑出待写入值。
*   **E203 (Bumblebee)**: 采用了 **字节掩码** 方案。通过 LSU 控制器产生 `wmask[3:0]` 信号，利用 ICB 总线协议传递至支持字节写使能的存储器。

## 3. 非对齐访问（Misaligned Access）讨论

### 3.1 定义与规则
当访问地址不满足其数据类型的自然边界时（例如 `SW` 指令访问地址 `0x1002`），即发生非对齐访问。RISC-V 基础指令集（RV32I）要求：
*   **Word (32-bit)**: 地址低两位必须为 `2'b00`。
*   **Halfword (16-bit)**: 地址最低位必须为 `1'b0`。

### 3.2 硬件处理策略
硬件处理非对齐访问存在两种策略：
1.  **硬件透明支持**：LSU 自动将跨字访问拆分为两次物理访存并进行数据拼接。该方案显著增加控制逻辑复杂度并降低访存吞吐率。
2.  **异常触发（当前项目选择）**：硬件不提供自动拆分逻辑，而是监测地址合法性。若检测到非对齐，则触发异常信号。

### 3.3 当前项目实现
当前设计已在 `exu_lsu.v` 中实现了静态对齐检测逻辑：
*   **检测逻辑**：基于 `lsu_req_info_size`（访问尺寸）对 `mema_addr` 的低两位进行逻辑判断。
*   **处理动作**：
    *   输出 `o_lsu_misaligned_exc` 异常信号。
    *   自动屏蔽当前周期的访存写使能（`o_mema_wren_exu`）和读请求，防止非法地址污染内存。
    *   在仿真环境（`SIMULATION` 宏开启）下，实时打印非法访问的地址与尺寸信息。

## 4. 结论与后续建议
针对高性能与逻辑简洁性的平衡，本项目最终选定“字节掩码（Byte-Strobe）”作为精细化写入方案，并明确“不支持硬件非对齐访问”作为架构约束。

**后续开发建议：**
1.  **存储器升级**：确保后端 DTCM 模块支持 4 位独立的字节写使能接口。
2.  **异常处理机制**：将 `o_lsu_misaligned_exc` 接入 CPU 的捕获逻辑，更新 `mcause` 寄存器以支持软件陷阱处理。
3.  **数据对齐偏移**：在 `LSU` 阶段，需根据地址低两位对写入数据执行相应的移位操作（Shift），以匹配物理存储位置。
